提供されるSkills（技術ナレッジベース）の内容を元に、高品質なZenn本のチャプターを執筆してください。

---

## 品質基準（厳守）

### 文体
- **です/ます調で統一**（だ/である調を絶対に混ぜない）
- 読者に語りかけるように丁寧に
- 専門用語は初出時に簡潔に説明

### 構成（各章共通）
- 先頭にfrontmatter: `---\ntitle: "章タイトル"\n---`
- **250〜400行**（これを超えてはいけない。超えそうなら内容を厳選する）
- 章末に**「まとめ」テーブル**（| 概念 | 要点 | 形式、導入章は不要）
- 章末に**「やってみよう！」セクション**（2〜3問の練習課題、導入章・最終章は不要）
- 最後に「次の章では〜を学びます。」で次章への導線（最終章は不要）

### 誠実性ルール（最重要）

この本はAIが生成したものであり、著者が実体験に基づいて書いたものではありません。
そのため、以下のルールを**絶対に守ってください**。

#### 禁止表現（使ってはいけない）
| 禁止 | 理由 |
|------|------|
| 「実測した」「実測値」 | 実際に測定していない |
| 「筆者の経験では」「私の経験上」 | 著者の実体験ではない |
| 「試した結果」「検証した結果」 | 実際に検証していない |
| 「〜を実現しました」「〜を達成しました」 | 実績の主張 |
| 「〜が改善しました」「〜が向上しました」 | 過去形での断定 |
| 「確認できました」 | 実際に確認していない |
| 「体感で〜倍」 | 主観的な体験の主張 |

#### 推奨表現（代わりに使う）
| 推奨 | 用途 |
|------|------|
| 「〜と言われています」 | 一般的な知見を紹介 |
| 「〜が一般的です」 | 業界標準を説明 |
| 「〜が期待できます」 | 効果の見込みを説明 |
| 「〜が想定されます」 | 結果の予測 |
| 「〜とされています」 | 権威ある情報の引用 |
| 「〜が推奨されます」 | ベストプラクティス |
| 「〜の傾向があります」 | 統計的な傾向 |
| 「公式ドキュメントによると〜」 | 出典の明示 |

#### OK表現（使ってよい）
- 「実際に手を動かしてみましょう」（読者への呼びかけ）
- 「実際に実行すると〜が表示されます」（コードの動作説明）
- 「実際の開発現場では〜」（一般論としての現場の話）

### コード例
- 必ず言語を指定（```typescript, ```python, ```bash 等）
- コピペで動作しそうなレベルの正確さ
- 必要最小限のコメントを付ける

### Zenn固有フォーマット
- 補足情報: `:::message\n内容\n:::`
- 警告: `:::message alert\n内容\n:::`
- テーブルはMarkdown標準形式

## 本の作成手順

### Step 1: config.yaml の作成

```yaml
title: "本のタイトル 2026"
summary: "本の説明文（1〜2文）"
topics: ["topic1", "topic2", "topic3", "topic4", "topic5"]
published: false
price: 1000
toc_depth: 0
chapters:
  - 00-introduction
  - 01-chapter-slug
  - 02-chapter-slug
  # ... 最大14章（00〜14）が標準
```

- topics: Zennで使われている既存のトピック名を5つ選ぶ
- price: 基礎本は500、実践本は1000
- published: 必ず false で作成（レビュー後に公開）

### Step 2: 各章の執筆

提供されるSkills（元ネタ）を読み込み、各章を執筆してください。

#### 章の構成テンプレート

```markdown
---
title: "章タイトル"
---

# 章タイトル

導入文（2〜3文で、この章で何を学ぶかを説明）

---

## セクション1

本文...

## セクション2

本文...

---

## まとめ

| 概念 | 要点 |
|------|------|
| セクション1 | 1行で要約 |
| セクション2 | 1行で要約 |

---

## やってみよう！

### 練習1: タイトル

問題文...

### 練習2: タイトル

問題文...

---

次の章では、〜を学びます。
```
