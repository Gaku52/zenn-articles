## レビュー基準

### 1. 文体・トーン
- **です/ます調で統一されているか**（だ/である調が混在していないか）
- 読者に語りかける丁寧な文体か
- 技術用語は正確か

### 2. 構成・フォーマット
- 先頭に正しいfrontmatterがあるか（`---\ntitle: "章タイトル"\n---`）
- 章の長さが**250〜400行**の範囲内か（超過・不足を指摘）
- 章末に**「まとめ」テーブル**があるか（導入章を除く）
- 章末に**「やってみよう！」セクション**があるか（導入章・最終章を除く）
- 「次の章では〜」で次章への導線があるか（最終章を除く）
- 見出しレベルが適切か（H1は章タイトルのみ、以降H2/H3）

### 3. 誠実性チェック（最重要）
以下の表現は**絶対に使ってはいけません**。見つけた場合は必ず指摘してください：

#### 禁止表現
- 「実測した」「実測値」「計測した結果」（実際に測定していないため）
- 「筆者の経験では」「私の経験上」（著者の実体験ではないため）
- 「試した結果」「検証した結果」「確認できました」（実際に検証していないため）
- 「〜を実現しました」「〜を達成しました」（実績を主張する表現）
- 「〜が改善しました」「〜が向上しました」（過去形で断定する表現）
- 「体感で〜倍」「体感的に」（主観的な実体験の主張）

#### 推奨される代替表現
- 「〜と言われています」「〜が一般的です」
- 「〜が期待できます」「〜が想定されます」
- 「〜とされています」「〜が推奨されます」
- 「〜の傾向があります」「〜のケースが多いです」
- 「公式ドキュメントによると〜」「〜という報告があります」

### 4. コンテンツ品質
- コード例が正確で動作しそうか（明らかな構文エラーがないか）
- 説明が論理的で矛盾がないか
- 同じ内容の不必要な繰り返しがないか
- 情報が古くないか（2026年時点の最新情報か）
- 章の内容が章タイトルと一致しているか

### 5. Zenn固有のフォーマット
- `:::message` / `:::` の情報ボックスが正しく閉じているか
- コードブロックの言語指定があるか（```typescript, ```bash 等）
- テーブルのMarkdown構文が正しいか
