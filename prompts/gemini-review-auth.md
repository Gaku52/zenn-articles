## 認証認可固有のレビュー観点

上記の共通基準に加え、以下の観点を**特に厳格に**チェックしてください：

- **セキュリティ上の誤りがないか**（この本の誤りは読者のアプリに脆弱性をもたらす）
- **パスワードハッシュのアルゴリズム推奨が適切か**（bcrypt/Argon2id推奨、MD5/SHA-1は非推奨と明記されているか）
- **JWT の署名検証の説明が正確か**（HS256 vs RS256の使い分け）
- **OAuth 2.0 のフローが正確か**（Authorization Code Flow, PKCE）
- **CSRF トークンの実装例が安全か**
- **セッション固定攻撃への対策が書かれているか**
- **トークンの保存場所の推奨が適切か**（localStorageのリスク、HttpOnly Cookieの推奨）
- **OIDC の ID Token と Access Token の違いが正確か**
- **RBAC/ABAC のコード例で権限チェック漏れがないか**
- **MFA の実装例が TOTP 仕様（RFC 6238）に準拠しているか**
- **非推奨・危険なプラクティスを推奨していないか**

## 共通レビュー基準

### 文体
- です/ます調で統一されているか

### 構成
- 各章250〜400行か
- 章末に「まとめ」テーブルがあるか（00章を除く）
- 章末に「やってみよう！」があるか（00章・14章を除く）
- 「次の章では〜」の導線があるか（14章を除く）

### 誠実性チェック（最重要）
以下の表現を見つけたら必ず指摘：
- 「実測した」「実測値」「計測した結果」
- 「筆者の経験では」「私の経験上」
- 「試した結果」「検証した結果」「確認できました」
- 「〜を実現しました」「〜を達成しました」「〜が向上しました」
- 「体感で〜倍」

推奨される代替表現：
- 「〜が期待できます」「〜が想定されます」「〜とされています」「〜が一般的です」

ただし以下はOK：
- 「実際に手を動かしてみましょう」（読者への呼びかけ）
- 「実際に実行すると〜」（コードの動作説明）
