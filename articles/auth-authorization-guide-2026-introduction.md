## 「認証まわり、なんとなくで実装していませんか？」

Next.jsのミドルウェアでセッションを取得する。JWTをlocalStorageに保存する。OAuth連携はライブラリに任せる。

動いてはいる。でも、こう聞かれたら答えられますか？

**「なぜHttpOnly Cookieに保存すべきなのか」「PKCEがなぜ必要なのか」「RBACとABACをどう使い分けるのか」**

認証認可は、Webアプリケーションのセキュリティの根幹です。しかし、仕組みを正確に理解し、適切に実装できるエンジニアは意外なほど多くありません。OWASP Top 10（2021）では、「アクセス制御の不備」が**1位**、「認証の不備」が**7位**にランクインしています。

---

**体系的に学ぶ機会がない。**

よく聞く悩みをまとめると：

- セッションとJWTのどちらを使うべきか、判断基準がない
- OAuth 2.0とOpenID Connectの違いを正確に説明できない
- CSRFトークンやSameSite Cookieの仕組みを理解せずに使っている
- RBACのロール設計で「ロール爆発」に悩んでいる
- Passkeysが話題だが、TOTPとの使い分けが分からない
- 「動くけどセキュリティ的に正しいか自信がない」コードがある

**そこで、認証認可の基礎から実装パターンまでを体系的にカバーする実践ガイドを執筆しました。**

## 本書の内容を一部紹介

### パスワードは「ハッシュ化すればOK」ではない

SHA-256やMD5でハッシュ化しているだけでは、レインボーテーブル攻撃で簡単に突破されます。本書では、NIST SP 800-63Bに準拠した実装を解説しています。

```typescript
import { hash, verify } from '@node-rs/argon2';

const hashedPassword = await hash(password, {
  memoryCost: 65536,  // 64 MB
  timeCost: 3,
  parallelism: 4,
});
```

bcryptとArgon2idの使い分け、Have I Been Pwned APIによる漏洩チェック、コスト係数のベンチマーク方法まで詳しく解説しています。

### OAuth 2.0のPKCEを「なぜ必要か」から理解する

「PKCEを有効にしてください」と言われて有効にしている方は多いでしょう。でも、なぜ必要なのか——Authorization Code横取り攻撃の仕組みと、PKCEがそれをどう防ぐかを図解付きで解説しています。

### RBACの「ロール爆発」をABACで解決する

ユーザーが増え、要件が複雑になると、ロールの数が爆発的に増加します。本書では、RBACとABACを組み合わせたハイブリッドアプローチで、柔軟かつ管理可能なアクセス制御を実現する方法を解説しています。

## 認証認可は「後から直せない」

認証認可の設計ミスは、プロダクトがスケールした後では修正コストが極めて高くなります。セッション方式からトークン方式への移行、権限モデルの再設計——いずれも大規模な改修を伴います。

本書は、最初から正しい設計判断ができるように、各技術の「なぜ」を丁寧に解説しています。セキュリティは後付けではなく、設計段階から組み込むもの。本書がその助けになれば幸いです。
