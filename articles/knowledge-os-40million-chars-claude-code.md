# 知識OSを作る #1 — 4,300万字超の技術知識体系をClaude Codeで構築している話

> この記事は「知識OSを作る」シリーズの第1回です。個人で構築している4,300万字超の技術知識体系を、サービスとして世に出すまでの全記録を連載していきます。

個人で4,300万字超の技術知識体系を構築しています。

小説に換算すると約80冊分。36のスキル領域、952のガイドドキュメント、8つのカテゴリ。これらが相互参照で繋がり、品質スコア平均90.3/100で維持されている。

なぜこんなものを作っているのか。どうやって作っているのか。そしてこれが何になるのか。

---

## なぜ作っているのか

理由はシンプルです。**自分が作りたいWebアプリがあるから**。

アプリを作るとき、必要な技術スタックはプロジェクトごとに変わります。認証が必要ならOAuthやJWTの知識がいる。パフォーマンスが求められるならキャッシュ戦略やCDN設計の知識がいる。iOSアプリならSwiftUIの設計パターンが必要になる。

その都度ゼロから調べるのは遅い。

だから、**あらゆる技術領域を体系的にまとめておいて、必要なときに即座に引き出せる状態**を作ろうと考えました。それがClaude Code Skillsとして形になったものです。

結果として、このSkillsを使えば**高速で品質の高いアプリケーションやサービスをユーザーに提供できる**。それが目的です。

## 各スキルの内部構造

36のスキルは、すべて同じ構造で統一されています。

```
skill-name/
├── SKILL.md          # スキル概要・目次
├── README.md         # 使用方法
├── docs/             # 本体（番号付きガイド群）
│   ├── 00-fundamentals/
│   │   ├── 00-overview.md
│   │   ├── 01-core-concepts.md
│   │   └── 02-practical-basics.md
│   ├── 01-advanced/
│   └── 02-practical/
├── checklists/       # クイックリファレンス
├── references/       # 外部リソースリンク
└── templates/        # コード・設定テンプレート
```

この統一構造が重要です。どのスキルを開いても、同じ場所に同じ種類の情報がある。人間が読むときも、AIが読むときも、迷わない。

## 品質エンジニアリング

4,300万字超の知識体系は、量だけでは意味がありません。**中身が薄ければ、いくらあっても使えない。**

### 品質基準：MITレベルを目指す

私が設定した品質基準は「MITの講義で使っても恥ずかしくないレベル」です。

具体的には100点満点のルーブリックを定義し、以下を評価しています。

- **構造**: 適切な見出し階層、学習目標の明示
- **コンテンツ**: 実践的なコード例、具体的な数値データ
- **相互参照**: 関連トピックへのリンク、前提知識の明示
- **サイズ**: 1ガイドあたり最低4万字以上の十分な深さ

### 品質検証のプロセス

自動採点システムではありません。**独自のプロンプトを設計し、Claude Codeに品質検証を依頼する**というプロセスです。

具体的にはNode.jsで書いた検証スクリプト群を使います。

```
_meta/scripts/
├── quality-audit.js          # 品質監査（100点満点採点）
├── cross-reference-audit.js  # 相互参照の整合性検証
├── expand-content.js         # コンテンツ拡充（11種テンプレート）
├── fix-broken-links.js       # 壊れたリンク自動修正
├── pad-undersized.js         # サイズ不足の検出・補完
├── auto-fix-sections.js      # セクション構造の修正
└── analyze-warnings.js       # WARNING分析
```

これらのスクリプトを通して、952ファイルすべてを検証しています。

## なぜここまでやるのか

よく聞かれます。「なぜそこまでやるの？」と。

答えはいくつかあります。

**実利的な理由**: アプリやサービスを作るとき、適切な技術スタックを選択したい。選択した後に、その技術の効力を最大限発揮するものになっているか確認したい。中途半端な知識で作ったものは、中途半端なサービスにしかならない。

**未来への投資**: AIは急速に進化しています。今後、より高性能なAIが登場したとき、**質の高い知識体系を持っている人間**がより素晴らしいサービスを作れる。AIの性能が上がるほど、この知識体系の価値も上がる。

**そして、一番の理由**:

多くの人を喜ばせたい。幸せにしたい。何より、**自分が幸せでありたい。技術に感動したい。**

だから、毎日やっています。

## 4,300万字超のリポジトリが「動く」ということ

正直に言います。4,300万字超規模のリポジトリが実際に動作していること自体が、とんでもないことだと思っています。

Claude CodeのSkillsとして読み込まれ、必要な知識が適切なタイミングで引き出される。相互参照を辿って関連知識に到達する。品質スコアに基づいて信頼性を判断する。

これは単なるドキュメント置き場ではありません。**知識が構造化され、検証され、相互に接続された「OS」**です。

そして、この知識体系は今後も加算していく予定です。新しい技術が登場すれば追加する。既存の知識が古くなれば更新する。成長し続けるシステムです。

- 「永遠の初心者」感から脱出するための成長設計
