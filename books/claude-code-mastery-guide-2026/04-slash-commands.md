# スラッシュコマンド

Claude Codeには、インタラクティブセッション中に素早く操作を実行できる**スラッシュコマンド**が用意されています。この章では、組み込みのスラッシュコマンドを網羅的に解説し、日々の開発作業を効率化する方法を学びます。

## スラッシュコマンドとは

スラッシュコマンドは、対話セッション中に `/` で始まる特殊なコマンドを入力することで実行できる、組み込みの固定ロジック操作です。

```bash
# コマンドの基本形式
/command [引数]

# 例
/help
/model
/compact Focus on API changes
```

重要な特徴として、スラッシュコマンドは**AIの推論を含まない即座の操作**です。Claudeに質問や依頼をするのではなく、Claude Codeのシステム機能を直接呼び出します。そのため、レスポンスが高速で、予測可能な結果が得られます。

## 会話管理コマンド

セッションの履歴やコンテキストを管理するコマンド群です。

### `/compact` — 会話履歴の圧縮

長時間のセッションでは、会話履歴が膨大になりコンテキストウィンドウを圧迫します。`/compact` コマンドは、これまでの会話を要約し、重要な情報だけを保持しながらトークン使用量を削減します。

```bash
# 基本的な圧縮
/compact

# カスタム指示付き圧縮
/compact Focus on API changes and database schema
/compact Keep all TypeScript type definitions
/compact Preserve error messages and debugging context
```

**使用タイミング**：
- コンテキストウィンドウが80%を超えた時
- 新しいトピックに移行する前
- メモリ警告（⚠️ MEMORY WARNING）が表示された時

**注意点**：
- 圧縮後は過去の詳細な会話内容にアクセスできなくなります
- 圧縮前に重要な情報をメモしておくことを推奨します

### `/clear` — 会話のクリア

現在の会話を完全にクリアし、新しいセッションを開始します。

```bash
/clear
```

`/compact` との違い：
- `/compact` は要約を保持、`/clear` は完全削除
- `/clear` 後は完全にクリーンな状態から開始
- プロジェクトコンテキスト（CLAUDE.md等）は保持されます

**使用タイミング**：
- まったく新しいタスクを開始する時
- トラブルシューティングで混乱した会話をリセットしたい時
- セッションが重くなりすぎた時

### `/diff` — 変更履歴のインタラクティブビュー

Claudeが行った全てのファイル変更を、インタラクティブなdiffビューアで確認できます。

```bash
/diff
```

このコマンドを実行すると：
1. セッション中の全変更がリスト表示されます
2. 矢印キーで変更を選択
3. 各変更の詳細なdiffを確認
4. 必要に応じて変更を元に戻すことが可能

**使用タイミング**：
- 大規模なリファクタリング後の確認
- 意図しない変更がないかチェック
- 変更内容をレビューしてからコミット

## モデル・動作制御コマンド

Claude Codeの動作モードやモデルを制御するコマンド群です。

### `/model` — モデルの切り替え

使用するClaudeモデルを切り替えます。

```bash
/model
```

実行すると、選択可能なモデルが表示されます：
- **Claude Opus 4.6** — 最も高性能、複雑なタスク向け
- **Claude Sonnet 4.5** — バランス型、日常的な開発作業向け（デフォルト）
- **Claude Haiku 3.5** — 高速・低コスト、シンプルなタスク向け

**選択基準**：
- **複雑なアーキテクチャ設計、難解なバグ修正** → Opus
- **通常のコーディング、リファクタリング** → Sonnet
- **単純なコード生成、ドキュメント作成** → Haiku

モデルはセッション中いつでも切り替え可能で、会話履歴は保持されます。

### `/cost` — コスト表示

現在のセッションで消費したAPIコストを表示します。

```bash
/cost
```

表示内容：
- 入力トークン数と費用
- 出力トークン数と費用
- 合計費用（USD）
- 使用モデルの内訳

**活用方法**：
- 定期的にコストをチェックし、予算管理
- モデル切り替えの判断材料に
- 効率的なプロンプト設計の効果測定

### `/context` — コンテキスト使用量の表示

現在のコンテキストウィンドウ使用状況を表示します。

```bash
/context
```

表示内容：
- 現在のトークン使用量
- 最大コンテキストサイズ
- 使用率（%）
- 主要なコンテンツの内訳（会話履歴、ファイル、プロジェクト設定等）

**80%を超えたら**：
1. `/compact` で圧縮を検討
2. 不要なファイルの読み込みを避ける
3. タスクを分割して新しいセッションで実行

## メモリ・設定コマンド

Claude Codeの設定やメモリ機能を管理するコマンド群です。

### `/memory` — メモリ管理

CLAUDE.mdやrulesファイルの一覧表示、Auto Memoryのオン/オフを切り替えます。

```bash
/memory
```

実行すると以下が表示されます：
- グローバルルール（`~/.claude/CLAUDE.md`）
- プロジェクトルール（`./CLAUDE.md`）
- Auto Memory機能の状態
- 現在適用されているメモリコンテキスト

**Auto Memoryとは**：
- Claudeが会話から重要な情報を自動記憶
- 次回セッションで文脈を維持
- プライバシー重視の場合はオフに

### `/config` — 設定管理

Claude Codeの設定を表示・変更します。

```bash
/config
```

設定可能な項目：
- デフォルトモデル
- エディタ設定
- ターミナル設定
- プロキシ設定
- 認証情報

### `/mcp` — MCPサーバー管理

Model Context Protocol（MCP）サーバーの状態確認と認証を行います。

```bash
/mcp
```

表示内容：
- 接続中のMCPサーバー一覧
- 各サーバーの状態（接続中/切断/エラー）
- 利用可能なツール
- 認証状態

**MCPサーバーとは**：
外部サービス（GitHub、Slack、Notion等）との統合を提供する拡張機能です。詳細は第7章で解説します。

### `/hooks` — フック管理

イベント駆動の自動化フック（PreToolUse、PostToolUse等）を管理します。

```bash
/hooks
```

フックの用途例：
- ツール実行前のバリデーション
- 実行後のログ記録
- メモリ監視と自動圧縮
- カスタムワークフローのトリガー

詳細は第6章「Hooks」で解説します。

## 開発支援コマンド

開発作業を効率化するコマンド群です。

### `/add-dir` — 追加作業ディレクトリの指定

複数のディレクトリを跨ぐプロジェクトで、追加の作業ディレクトリを指定します。

```bash
/add-dir /path/to/another/project
```

**使用例**：
```bash
# メインプロジェクト: /Users/gaku/my-app
# APIサーバー: /Users/gaku/my-api
# 両方を同時に操作したい場合

/add-dir /Users/gaku/my-api
```

これにより、Claudeは両方のディレクトリのファイルにアクセスし、統合的な作業が可能になります。

### `/agents` — エージェント管理

並列実行中のタスクエージェントを管理します。

```bash
/agents
```

表示内容：
- 実行中のエージェント一覧
- 各エージェントのタスク
- 進行状況
- 完了したエージェントの結果

エージェントの活用については第8章で詳しく解説します。

### `/vim` — Vimキーバインディング

Vimスタイルのキーバインディングを有効化します。

```bash
/vim
```

有効化すると：
- `j/k` で履歴ナビゲーション
- `i` で入力モード
- `Esc` でコマンドモード
- その他の基本的なVimコマンド

Vimユーザーには馴染みのある操作感でClaude Codeを使用できます。

### `/ide` — IDE統合管理

エディタ統合（VS Code、Cursor等）の状態を確認・設定します。

```bash
/ide
```

設定可能な項目：
- デフォルトエディタ
- エディタで開く際のパス解決
- 統合機能のオン/オフ

## 診断コマンド

問題発生時のトラブルシューティングに使用するコマンド群です。

### `/doctor` — システム診断

Claude Codeの動作環境を診断し、問題を検出します。

```bash
/doctor
```

診断項目：
- Node.jsバージョン
- 依存パッケージの整合性
- 設定ファイルの妥当性
- MCPサーバーの接続状態
- APIキーの有効性
- ネットワーク接続

**問題が検出された場合**：
- 具体的なエラーメッセージ
- 推奨される修正方法
- 参考ドキュメントへのリンク

### `/bug` — バグ報告

Claude Codeのバグを報告するためのテンプレートを生成します。

```bash
/bug
```

実行すると：
1. システム情報の自動収集
2. 再現手順の入力プロンプト
3. GitHubのissueテンプレート生成
4. ブラウザでissue作成ページを開く

### `/help` — コマンド一覧

全てのスラッシュコマンドの一覧と簡単な説明を表示します。

```bash
/help
```

**使用タイミング**：
- コマンドを忘れた時
- 新機能の確認
- クイックリファレンスとして

## 高度なコマンド

特殊な用途や高度な使い方に関するコマンド群です。

### `/export` — セッションのエクスポート

現在のセッション（会話履歴、変更履歴、コンテキスト）を外部ファイルにエクスポートします。

```bash
/export
```

エクスポート形式：
- JSON（機械可読）
- Markdown（人間可読）
- HTML（レポート形式）

**活用例**：
- 作業記録として保存
- チームメンバーとの共有
- ドキュメント生成の素材
- 長期的な学習データの蓄積

### `/extra-usage` — 追加使用量のオプトイン

Proプランで、月次制限を超えて追加使用量を購入する際にオプトインします。

```bash
/extra-usage
```

このコマンドを実行すると：
1. 現在の使用量と制限が表示されます
2. 追加料金の確認
3. オプトインの確認プロンプト

**注意**：
- Freeプランでは使用不可
- 追加料金が発生します
- 月初にリセットされます

## コマンドの組み合わせと実践例

スラッシュコマンドは単独でも便利ですが、組み合わせることでより強力になります。

### 例1: 大規模リファクタリングのワークフロー

```bash
# 1. コンテキストを確認
/context

# 2. 必要に応じて圧縮
/compact Keep all type definitions and API contracts

# 3. リファクタリング実行（Claudeに依頼）
"認証モジュールをリファクタリングして、依存性注入パターンに変更してください"

# 4. 変更内容を確認
/diff

# 5. コストをチェック
/cost
```

### 例2: 新しいプロジェクトの開始

```bash
# 1. 会話をクリア
/clear

# 2. 追加ディレクトリを指定（必要に応じて）
/add-dir /path/to/shared/components

# 3. メモリ設定を確認
/memory

# 4. プロジェクト開始
"新しいNext.jsプロジェクトをTypeScript + Tailwindでセットアップしてください"
```

### 例3: トラブルシューティング

```bash
# 1. システム診断
/doctor

# 2. MCP接続確認
/mcp

# 3. 設定確認
/config

# 4. 問題が解決しない場合
/bug
```

## スラッシュコマンドのベストプラクティス

### 1. 定期的なコンテキスト管理

```bash
# 長時間セッションでは30分ごとに確認
/context

# 80%を超えたら圧縮
/compact Preserve current task context
```

### 2. モデル選択の最適化

```bash
# 複雑なタスクの開始時
/model
# → Opusを選択

# 単純な作業に切り替える時
/model
# → Haikuを選択してコスト削減
```

### 3. 変更の定期的な確認

```bash
# 大きな変更の前後で必ず確認
/diff
```

### 4. コスト意識

```bash
# 大規模な作業の前に現在のコストを確認
/cost

# 予算に応じてモデルやアプローチを調整
```

## まとめ

本章で解説したスラッシュコマンドを以下にまとめます。

| コマンド | 用途 | 使用頻度 |
|---------|------|---------|
| `/compact [instructions]` | 会話履歴の圧縮 | 高 |
| `/clear` | 会話のクリア | 中 |
| `/diff` | 変更履歴の確認 | 高 |
| `/model` | モデル切り替え | 中 |
| `/cost` | コスト表示 | 中 |
| `/context` | コンテキスト使用量表示 | 高 |
| `/memory` | メモリ管理 | 低 |
| `/config` | 設定管理 | 低 |
| `/mcp` | MCPサーバー管理 | 低 |
| `/hooks` | フック管理 | 低 |
| `/add-dir` | 追加ディレクトリ指定 | 中 |
| `/agents` | エージェント管理 | 中 |
| `/vim` | Vimキーバインディング | 低 |
| `/ide` | IDE統合管理 | 低 |
| `/doctor` | システム診断 | 低 |
| `/bug` | バグ報告 | 低 |
| `/help` | コマンド一覧表示 | 低 |
| `/export` | セッションエクスポート | 低 |
| `/extra-usage` | 追加使用量オプトイン | 低 |

**特に重要なコマンド**：
- `/context` と `/compact` — メモリ管理の基本
- `/diff` — 変更の確認と品質保証
- `/model` と `/cost` — 効率とコストのバランス
- `/help` — 困った時の頼れる味方

## やってみよう！

### 練習課題1: コンテキスト管理

以下のシナリオで適切なコマンドを選択してください：

1. 1時間のペアプロセッション後、コンテキストが90%に達しました
2. 新しい機能開発に移る前に、これまでの作業内容をクリーンにしたい
3. 重要なAPI設計の議論だけを残して、デバッグログは削除したい

**解答例**：
1. `/compact` を実行してコンテキストを圧縮
2. `/clear` を実行して完全に新しいセッションを開始
3. `/compact Preserve all API design discussions and architectural decisions` でカスタム圧縮

### 練習課題2: 効率的なモデル選択

以下のタスクに最適なモデルを選び、その理由を説明してください：

1. 既存のコードに簡単なログ出力を10箇所追加
2. 複雑なマイクロサービスアーキテクチャの設計レビュー
3. TypeScriptの型定義ファイルを自動生成

**解答例**：
1. **Haiku** — 単純な定型作業なので高速・低コストなHaikuが最適
2. **Opus** — 複雑な設計判断が必要なのでOpusの高度な推論能力が必要
3. **Sonnet** — 型推論は複雑だが、定型的なパターンも多いのでバランス型のSonnetが適切

### 練習課題3: トラブルシューティングフロー

Claude Codeが突然エラーを出して動作しなくなりました。どのようなコマンドをどの順序で実行しますか？

**解答例**：
```bash
# 1. システム診断で問題を特定
/doctor

# 2. MCP接続の確認（MCPサーバーが原因の可能性）
/mcp

# 3. 設定の確認
/config

# 4. 会話履歴が原因の可能性があれば
/clear

# 5. 問題が解決しない場合
/bug
```
