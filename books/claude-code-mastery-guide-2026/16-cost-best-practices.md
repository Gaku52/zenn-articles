# コスト管理とベストプラクティス

この最終章では、Claude Codeを効率的に活用するためのコスト管理手法と、実践で役立つベストプラクティスを総まとめします。これまでに学んだすべての知識を統合し、持続可能な開発ワークフローを構築しましょう。

## サブスクリプションプラン（2026年）

Claude Codeは以下のサブスクリプションプランで提供されています。

### Pro: $20/月

- 年間契約で$17/月
- カジュアルな個人開発者向け
- 基本的なClaude Codeの機能をすべて利用可能
- 月間の使用量に標準的な制限あり

### Max: $100〜$200/月

- 5倍または20倍の使用量乗数
- 集中的なコーディング作業に適している
- プロフェッショナル開発者やヘビーユーザー向け
- より大規模なプロジェクトや長時間のセッションに対応

### Team/Enterprise

- チーム向けの専用プラン
- 組織全体での利用を想定
- カスタマイズ可能な使用量と権限管理
- サポートとSLAの提供

## 実際のコスト感覚

実運用でのコストは以下のような傾向があります。

### 日次コスト

- **1日あたり平均**: $6/開発者
- **90%のユーザー**: 1日$12未満
- **ヘビーユーザー**: $20〜$30/日（Maxプラン推奨）

### 月次コスト

- **Sonnet使用時の平均**: $100〜$200/月
- **Opus中心の場合**: $200〜$400/月
- **Haiku活用で最適化**: $50〜$100/月

これらの数値は、適切なモデル選択とコンテキスト管理を行った場合の目安です。

## APIトークン価格（参考）

API経由でClaude モデルを使用する場合の価格は以下の通りです（2026年3月時点）。

| モデル | 入力 | 出力 |
|--------|------|------|
| Opus 4.6 | $15/1M tokens | $75/1M tokens |
| Sonnet 4.5 | $3/1M tokens | $15/1M tokens |
| Haiku 4.5 | $0.80/1M tokens | $4/1M tokens |

Claude Codeのサブスクリプションには、これらのAPI料金は含まれていませんが、サブスクリプション内の使用量制限はこれらの価格を基準に設定されています。

## コスト最適化の戦略

効率的にClaude Codeを活用するための、具体的なコスト削減テクニックを紹介します。

### 1. モデル使い分け

タスクの複雑さに応じて最適なモデルを選択します。

```bash
# 日常的なコーディング作業
claude --model sonnet-4-5

# 複雑なアーキテクチャ設計
claude --model opus-4-6

# シンプルなスクリプト生成
claude --model haiku-4-5
```

**使い分けの目安**:

- **Opus 4.6**: 複雑な設計、難解なバグ修正、アーキテクチャレビュー
- **Sonnet 4.5**: 通常の開発作業、リファクタリング、テスト作成（デフォルト推奨）
- **Haiku 4.5**: 単純なスクリプト生成、定型的なコード変換、ドキュメント整形

### 2. サブエージェントにHaikuを使う

Skillsのmanifest.jsonでサブエージェントのモデルを指定できます。

```json
{
  "name": "format-code",
  "instructions": "コードをフォーマットするスキル",
  "model": "claude-haiku-4-5"
}
```

単純なタスクを実行するSkillsには、低コストなHaikuを割り当てることで、全体のコスト削減につながります。

### 3. CLAUDE.mdで再説明を削減

プロジェクトの基本情報やルールをCLAUDE.mdに記載しておけば、毎回同じ説明をする必要がなくなります。

```markdown
# プロジェクト固有ルール

## コーディング規約
- インデントは2スペース
- 変数名はcamelCase
- 関数名は動詞で始める

## テスト要件
- すべての公開関数にユニットテストを書く
- カバレッジは80%以上を維持
```

これにより、毎回のプロンプトが短くなり、入力トークンを削減できます。

### 4. `/compact`で定期圧縮

長時間のセッションでは、定期的に`/compact`コマンドを実行してコンテキストを圧縮します。

```bash
# コンテキスト使用率を確認
/context

# 不要な履歴を削除して圧縮
/compact
```

特に以下のタイミングで実行すると効果的です。

- 大きなタスクが完了した後
- コンテキスト使用率が80%を超えた時
- メモリ警告が表示された時

### 5. プロンプトキャッシング

API使用時には、プロンプトキャッシングを活用することで最大90%のコスト削減が可能です。

Claude Codeでは内部的に自動でキャッシングが行われていますが、API経由で使用する場合は明示的に設定できます。

```python
# Anthropic APIでのプロンプトキャッシング例
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-5-20250929",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "長いシステムプロンプト...",
            "cache_control": {"type": "ephemeral"}
        }
    ],
    messages=[{"role": "user", "content": "質問"}]
)
```

### 6. エフォートレベルの調整

シンプルなタスクには`--effort low`を指定してコストを削減できます。

```bash
# 低エフォートモード（シンプルなタスク向け）
claude --effort low "このJSONをYAMLに変換して"

# 通常モード（デフォルト）
claude "複雑なアルゴリズムを実装して"

# 高エフォートモード（複雑な設計向け）
claude --effort high "システム全体のアーキテクチャを設計して"
```

## トークン使用量の確認

コスト管理の第一歩は、現在の使用状況を把握することです。

### `/cost`コマンド

セッション全体のコストを確認できます。

```bash
/cost
```

表示される情報:

- 使用したトークン数（入力/出力）
- 推定コスト（モデル別）
- セッション時間
- モデル別の内訳

### `/context`コマンド

現在のコンテキスト使用率を確認できます。

```bash
/context
```

表示される情報:

- コンテキストウィンドウの使用率（%）
- 残り利用可能なトークン数
- メモリ状態の警告

## ベストプラクティス集

これまでの章で学んだ内容を、実践的なベストプラクティスとしてまとめます。

### 1. 1セッション1タスク

スコープを明確に保つことで、コンテキストの肥大化を防ぎます。

**良い例**:

```bash
# セッション1: ユーザー認証機能を実装
claude "ユーザー認証APIエンドポイントを実装して"

# セッション2: テストを追加
claude "認証機能のテストを書いて"
```

**悪い例**:

```bash
# 1つのセッションで複数の無関係なタスク
claude "認証機能を実装して、ついでにデザインも変えて、DBも最適化して"
```

### 2. 計画→実装の2段階

EnterPlanModeで先に設計を固めてから実装に移ります。

```bash
# Step 1: 計画モードで設計
/plan "決済システムの実装計画を立てて"

# Step 2: 実装
claude "計画に従って決済APIを実装して"
```

これにより、手戻りが減り、結果的にコストと時間を節約できます。

### 3. 小さく始める

一度に大量のファイルを変更せず、段階的に進めます。

**推奨アプローチ**:

1. 1つのモジュールから始める
2. 動作確認してからコミット
3. 次のモジュールに進む
4. リファクタリングは別セッションで

### 4. テストを先に書く

TDDでClaude Codeの品質を担保します。

```bash
# Step 1: テストを先に書く
claude "calculateDiscount関数のテストを書いて"

# Step 2: 実装
claude "テストをパスするようにcalculateDiscount関数を実装して"
```

これにより、期待する動作が明確になり、Claude Codeの出力精度が向上します。

### 5. CLAUDE.mdを育てる

使いながら継続的に改善し続けます。

```markdown
# 学んだことを追記

## よくあるミス
- 日付フォーマットはISO 8601を使用（過去に間違えた）
- APIレスポンスは必ずエラーハンドリングを含める

## プロジェクト固有の用語
- "ユーザー" = 一般利用者
- "管理者" = 社内スタッフ
- "オペレーター" = カスタマーサポート担当
```

### 6. Skillsで標準化

チームのワークフローをSkillsにまとめます。

```json
{
  "name": "api-endpoint",
  "instructions": "RESTful APIエンドポイントを標準形式で生成",
  "model": "claude-sonnet-4-5"
}
```

これにより、チーム全体で一貫した品質を保てます。

### 7. hooksで自動化

lint・format・テストをhooksで自動実行します。

```json
{
  "hooks": {
    "PostToolUse": {
      "Edit": "npm run lint -- {{file_path}}",
      "Write": "npm run format -- {{file_path}}"
    },
    "PostCommit": "npm test"
  }
}
```

手動でのチェックを忘れることがなくなり、品質が安定します。

### 8. 権限は最小限

deny設定で不要な操作をブロックします。

```json
{
  "permissions": {
    "deny": {
      "readPaths": [".env", "secrets/"],
      "writePaths": ["dist/", "node_modules/"],
      "executables": ["rm -rf", "sudo"]
    }
  }
}
```

事故を未然に防ぎ、安全な運用が可能になります。

## よくあるトラブルと対処法

実運用で遭遇しやすい問題とその解決方法をまとめます。

### コンテキストオーバーフロー

**症状**: "Context limit exceeded"エラーが表示される

**対処法**:

```bash
# 方法1: コンテキストを圧縮
/compact

# 方法2: セッションを分割
# 現在のタスクを完了させてから新規セッションを開始
```

**予防策**:

- 定期的に`/compact`を実行
- 1セッション1タスクを徹底
- 大きなファイルは部分的に読み込む（offset/limit使用）

### 期待と違う出力

**症状**: Claude Codeの出力が意図と異なる

**対処法**:

```bash
# 具体的な例を示す
claude "この関数をリファクタリングして。期待する出力例:
function calculateTotal(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}
のような、reduce を使った簡潔な実装にして"
```

**予防策**:

- プロンプトに具体例を含める
- CLAUDE.mdにルールを明記
- EnterPlanModeで事前確認

### MCPサーバーが接続できない

**症状**: MCP機能が動作しない

**対処法**:

```bash
# 状態確認
/mcp

# サーバー一覧確認
claude mcp list

# 特定サーバーの再起動
claude mcp restart <server-name>
```

**予防策**:

- settings.jsonの設定を確認
- サーバーの依存関係をインストール
- ログファイルでエラー内容を確認

### 権限エラー

**症状**: "Permission denied"エラーが表示される

**対処法**:

```bash
# settings.jsonのpermissionsセクションを確認
cat ~/.config/claude/settings.json | grep -A 10 "permissions"
```

必要に応じてallowPathsに追加:

```json
{
  "permissions": {
    "allow": {
      "readPaths": ["/Users/yourname/project/"],
      "writePaths": ["/Users/yourname/project/src/"]
    }
  }
}
```

### フックが動かない

**症状**: PostToolUseやPreCommitが実行されない

**対処法**:

```bash
# デバッグモードで確認
claude --debug "hooks"
```

表示されるログでフックの実行状況を確認し、コマンドのパスや構文をチェックします。

**予防策**:

- フックコマンドを事前にターミナルでテスト
- パスは絶対パスで指定
- エラー出力を確認できるようにする

### Claude Codeの本質

Claude Codeは「ツール」ではなく「開発パートナー」です。

- **人間**: 設計・判断・レビューに集中
- **Claude Code**: 実装・テスト・ドキュメント生成を担当

この役割分担を意識することで、最大の効果を得られます。

### 4つの活用の鍵

1. **CLAUDE.md**: プロジェクトのルールと文脈を共有
2. **Skills**: 繰り返すワークフローを標準化
3. **hooks**: 品質チェックを自動化
4. **MCP**: 外部ツールとの統合

これらを適切に組み合わせることが、Claude Code活用の核心です。
