# モデルの理解と選択

Claude Codeを効果的に使いこなすためには、まず**Claudeモデルファミリー**を理解し、タスクに応じて適切なモデルを選択することが重要です。この章では、2026年現在利用可能なClaudeモデルの特徴、切り替え方法、そしてタスク別の最適な使い分け戦略について解説します。

## Claudeモデルファミリー（2026年現在）

Anthropicが提供するClaudeモデルは、性能・速度・コストのバランスに応じて3つのティアに分かれています。

### Claude Opus 4.6 — 最上位モデル

**Claude Opus 4.6**は、2026年2月5日にリリースされた最新の最上位モデルです。コーディング、エージェント処理、プロフェッショナルな作業において世界最高性能を誇ります。

**主な特徴**
- **コンテキストウィンドウ**: 1Mトークン（約75万語）
- **最大出力トークン**: 128k（従来の2倍）
- **適応的推論（Adaptive Thinking）**: タスクの複雑さに応じて自動的に思考量を調整
- **用途**: 複雑なアーキテクチャ設計、大規模リファクタリング、高度な問題解決、レビュー

**適応的推論の仕組み**

Opus 4.6は、タスクの性質を判断し、必要に応じて深い思考プロセスを展開します。例えば、単純なバグ修正には短時間で応答し、複雑な設計判断には時間をかけて多角的に検討します。

```bash
# Opus 4.6を高エフォートで起動
claude --model claude-opus-4-6 --effort high
```

### Claude Sonnet 4.5 — バランス型

**Claude Sonnet 4.5**は、速度とコスト効率のバランスが取れたモデルです。日常的なコーディングタスクに最適で、Claude Codeのデフォルトモデルとして採用されています。

**主な特徴**
- **コンテキストウィンドウ**: 200kトークン
- **速度**: Opusの約2-3倍高速
- **コスト**: Opusの約1/5（入力）、1/5（出力）
- **用途**: 通常のコーディング、デバッグ、テスト作成、ドキュメント生成

**推奨利用シーン**
- 機能実装（CRUD、API統合、UI開発）
- バグ修正とデバッグ
- ユニットテスト・統合テスト作成
- コードレビューと改善提案

### Claude Haiku 4.5 — 高速・低コスト

**Claude Haiku 4.5**は、最も高速で低コストなモデルです。定型処理や大量のシンプルなタスクに最適です。

**主な特徴**
- **コンテキストウィンドウ**: 200kトークン
- **速度**: Opusの約5-10倍高速
- **コスト**: Opusの約1/19（入力）、1/19（出力）
- **用途**: ファイル検索、コード整形、定型処理、大量のシンプルなタスク

**推奨利用シーン**
- コード整形・リンター修正
- ファイル検索とGrep操作
- 簡単な質問応答
- サブエージェントによる定型タスク実行

## モデルの切り替え方法

Claude Codeでは、複数の方法でモデルを切り替えられます。タスクに応じて柔軟に選択しましょう。

### 1. `/model` コマンド（インタラクティブ）

セッション中に対話的にモデルを切り替える最も簡単な方法です。

```bash
# セッション中にモデル選択メニューを表示
/model
```

表示されるメニューから、使用したいモデルを選択します。

```
Select a model:
1. Claude Opus 4.6
2. Claude Sonnet 4.5 (current)
3. Claude Haiku 4.5
```

### 2. コマンドライン引数 `--model`

起動時にモデルを指定します。

```bash
# Opus 4.6で起動
claude --model claude-opus-4-6

# Sonnet 4.5で起動
claude --model claude-sonnet-4-5

# Haiku 4.5で起動
claude --model claude-haiku-4-5
```

### 3. `settings.json` でデフォルト設定

`~/.config/claude/settings.json` でデフォルトモデルを設定できます。

```json
{
  "model": "claude-sonnet-4-5",
  "availableModels": [
    "claude-opus-4-6",
    "claude-sonnet-4-5",
    "claude-haiku-4-5"
  ]
}
```

**設定項目の説明**
- `"model"`: デフォルトで使用するモデル
- `"availableModels"`: `/model` コマンドで選択可能なモデルリスト（不要なモデルを非表示にできる）

### 4. プロジェクト別設定（`.claude/settings.json`）

プロジェクトルートに `.claude/settings.json` を配置すると、そのプロジェクト専用のモデル設定が可能です。

```json
{
  "model": "claude-opus-4-6",
  "effortLevel": "high"
}
```

これにより、複雑なプロジェクトでは常にOpus 4.6を使用する、といった運用が可能になります。

## エフォートレベル（Opus 4.6限定）

**エフォートレベル**は、Opus 4.6専用の機能で、モデルがタスクにかける「思考の深さ」を制御します。

### エフォートレベルの種類

| レベル | 用途 | 思考時間 |
|--------|------|----------|
| **high** | 複雑な設計・アーキテクチャ判断・重要な意思決定 | 長い（30秒〜数分） |
| **medium** | 通常の開発タスク・コードレビュー | 中程度（5〜30秒） |
| **low** | シンプルな質問・小規模な修正 | 短い（1〜5秒） |

### 設定方法

**コマンドライン引数**

```bash
# 高エフォートで起動
claude --model claude-opus-4-6 --effort high

# 中エフォート（デフォルト）
claude --model claude-opus-4-6 --effort medium

# 低エフォート
claude --model claude-opus-4-6 --effort low
```

**settings.json**

```json
{
  "model": "claude-opus-4-6",
  "effortLevel": "high"
}
```

### エフォートレベルの使い分け

**high エフォートが適しているケース**
- マイクロサービスのアーキテクチャ設計
- セキュリティ脆弱性の分析
- 大規模リファクタリングの戦略立案
- パフォーマンス最適化の根本原因分析

**medium エフォートが適しているケース**
- 新機能の実装
- バグ修正とデバッグ
- コードレビュー
- テストケースの設計

**low エフォートが適しているケース**
- 簡単な質問への回答
- コードの整形・スタイル修正
- 変数名の提案
- ドキュメントの軽微な修正

## 適応的推論（Adaptive Thinking）

**適応的推論**は、Opus 4.6に搭載された最新の機能で、モデルが**コンテキストに応じて思考量を自動調整**します。

### 仕組み

従来のモデルは、タスクの複雑さに関わらず一定の思考プロセスを経ていました。Opus 4.6の適応的推論は以下のように動作します。

1. **タスク分析**: ユーザーの質問・リクエストの性質を判断
2. **複雑度評価**: 必要な思考の深さを自動推定
3. **動的思考**: シンプルなタスクには短時間、複雑なタスクには長時間思考
4. **応答生成**: 最適化された思考プロセスに基づき回答

### settings.json での設定

```json
{
  "model": "claude-opus-4-6",
  "thinking": {
    "type": "adaptive"
  },
  "alwaysThinkingEnabled": true
}
```

**設定項目の説明**
- `"type": "adaptive"`: 適応的推論を有効化（推奨）
- `"alwaysThinkingEnabled": true`: 常に思考プロセスを表示

### 適応的推論の効果

**シンプルなタスクの例**

```bash
Q: このファイルのimport文を整理して

→ 思考時間: 約2秒
→ 素早く整形して応答
```

**複雑なタスクの例**

```bash
Q: このマイクロサービスアーキテクチャのスケーラビリティ問題を分析して

→ 思考時間: 約45秒
→ 多角的な分析と具体的な改善案を提示
```

このように、適応的推論により、**無駄な待ち時間を削減しつつ、必要な場合は深く思考する**最適なバランスを実現します。

## タスク別モデル使い分け戦略

実務での効果的なモデル選択戦略を、タスク別に解説します。

### アーキテクチャ設計 → Opus 4.6

**推奨エフォート**: high

**適用シーン**
- マイクロサービス設計
- データベーススキーマ設計
- セキュリティアーキテクチャ
- パフォーマンス最適化戦略

**実行例**

```bash
claude --model claude-opus-4-6 --effort high

Q: 100万ユーザー対応のチャットアプリのアーキテクチャを設計して
```

Opus 4.6は、スケーラビリティ、可用性、コスト、セキュリティなど多角的に分析し、具体的な技術選定まで含めた設計を提案します。

### 日常コーディング → Sonnet 4.5

**推奨設定**: デフォルト（medium effort相当）

**適用シーン**
- CRUD機能実装
- API統合
- UI開発
- バグ修正
- テスト作成

**実行例**

```bash
claude  # デフォルトでSonnet 4.5

Q: ユーザー登録APIエンドポイントを実装して
```

Sonnet 4.5は、速度とコストのバランスが良く、日常的な開発タスクを効率的に処理します。

### 定型処理・大量処理 → Haiku 4.5

**推奨設定**: デフォルト

**適用シーン**
- コード整形
- ファイル検索
- 簡単な質問応答
- リンター修正
- 大量のシンプルなタスク

**実行例**

```bash
claude --model claude-haiku-4-5

Q: src/以下の全ファイルでconsole.logを削除して
```

Haiku 4.5は、高速かつ低コストで定型処理を大量に実行できます。

### サブエージェント → Sonnet/Haiku

**Task機能**を使う場合、サブエージェントには軽量モデルを割り当てると効率的です。

**settings.json 設定例**

```json
{
  "model": "claude-opus-4-6",
  "subagentModel": "claude-haiku-4-5"
}
```

**実行例**

```bash
# メインエージェント: Opus 4.6
# サブエージェント: Haiku 4.5

Q: 以下のタスクを並列処理して
   1. テストケース100件作成
   2. ドキュメント更新
   3. リンター修正
```

メインエージェントのOpusが全体を統括し、実際の定型作業はHaikuが高速処理します。

### ハイブリッド戦略（推奨）

実務では、**複数モデルを併用**することで、コストと性能を最適化できます。

**典型的なワークフロー**

1. **設計フェーズ**: Opus 4.6（high effort）でアーキテクチャ決定
2. **実装フェーズ**: Sonnet 4.5で機能実装
3. **整形・修正**: Haiku 4.5で定型処理
4. **レビュー**: Opus 4.6（medium effort）で最終確認

**1日の運用例**

```bash
# 朝: 設計レビュー（Opus）
claude --model claude-opus-4-6 --effort high
Q: 今日実装する認証機能の設計をレビューして

# 日中: 実装（Sonnet）
claude --model claude-sonnet-4-5
Q: JWT認証ミドルウェアを実装して

# 夕方: 整形・テスト（Haiku）
claude --model claude-haiku-4-5
Q: 全テストファイルを整形して実行して

# 夜: 最終レビュー（Opus）
claude --model claude-opus-4-6 --effort medium
Q: 今日実装したコードをレビューして
```

この戦略により、**品質を保ちながらコストを60-70%削減**できます。

| 項目 | Opus 4.6 | Sonnet 4.5 | Haiku 4.5 |
|------|----------|------------|-----------|
| **性能** | 最高 | 高 | 中 |

| **入力コスト** | $15/1M | $3/1M | $0.80/1M |

| **エフォートレベル** | ○ | - | - |
| **推奨用途** | 設計・アーキテクチャ | 日常コーディング | 定型処理・大量タスク |

**モデル選択の原則**

1. **複雑さで判断**: タスクが複雑なほど上位モデル
2. **頻度で判断**: 頻繁なタスクほど軽量モデル
3. **コストで判断**: 予算に応じてハイブリッド戦略
4. **速度で判断**: 急ぎのタスクはHaiku優先

**切り替え方法の原則**

1. **セッション中**: `/model` コマンド
2. **起動時指定**: `--model` フラグ
3. **デフォルト設定**: `settings.json`
4. **プロジェクト別**: `.claude/settings.json`

## やってみよう！

### 練習1: モデル切り替えを体験する

以下の手順で、3つのモデルの違いを体感してください。

```bash
# 1. Haiku 4.5で起動
claude --model claude-haiku-4-5
Q: Reactでカウンターコンポーネントを作成して

# 2. Sonnet 4.5で起動
claude --model claude-sonnet-4-5
Q: Reactでカウンターコンポーネントを作成して

# 3. Opus 4.6で起動
claude --model claude-opus-4-6 --effort high
Q: Reactでカウンターコンポーネントを作成して
```

**確認ポイント**
- 応答速度の違い
- コードの詳細度・説明の充実度
- 提案される設計パターンの違い

### 練習2: プロジェクト別設定を作成する

自分のプロジェクトに `.claude/settings.json` を作成し、最適なモデルを設定してください。

```bash
# プロジェクトルートで
mkdir -p .claude
cat > .claude/settings.json << 'EOF'
{
  "model": "claude-sonnet-4-5",
  "availableModels": [
    "claude-opus-4-6",
    "claude-sonnet-4-5",
    "claude-haiku-4-5"
  ]
}
EOF
```
