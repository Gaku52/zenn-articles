## Docker とは何か

### 一言でいうと

Docker は、アプリケーションを **コンテナ** という軽量な実行環境にパッケージングし、どこでも同じように動かせるようにするツールです。

もう少し正確に言うと、Docker はコンテナの**ビルド（構築）・配布・実行**を一貫して行えるプラットフォームです。

```
アプリのコード + 依存ライブラリ + 設定ファイル
        ↓ Dockerfile で定義
   コンテナイメージ（実行に必要なものが全部入ったパッケージ）
        ↓ docker run で起動
   コンテナ（隔離された実行環境でアプリが動く）
```

### コンテナのイメージ

日常の例えで考えてみましょう。コンテナは「持ち運べる箱」です。

- アプリケーションのコード
- アプリが動くために必要なライブラリやツール
- 設定ファイル

これらをすべて一つの箱（コンテナイメージ）に詰め込みます。この箱を誰かに渡せば、相手の環境でも全く同じようにアプリが動きます。「自分の PC では動くのに、本番サーバーでは動かない」という問題を解決するのが、Docker の最大の価値です。

### Docker の 3 つの柱

Docker を理解するうえで重要な 3 つの概念があります。

| 概念 | 説明 |
|---|---|
| **Dockerfile** | コンテナイメージの設計図。テキストファイルで「何をインストールして、どう設定するか」を宣言的に記述します |
| **イメージ** | Dockerfile からビルドされた、実行可能なパッケージ。読み取り専用で、バージョン管理ができます |
| **コンテナ** | イメージから起動された実行中のインスタンス。隔離された環境でアプリケーションが動作します |

```bash
# Dockerfile からイメージをビルド
docker build -t my-app:v1 .

# イメージからコンテナを起動
docker run -d -p 8080:80 my-app:v1

# 実行中のコンテナを確認
docker ps
```

## コンテナと仮想マシンの違い

Docker を理解するうえで避けて通れないのが、「仮想マシン（VM）との違い」です。どちらも「アプリケーションを隔離して実行する技術」ですが、仕組みが根本的に異なります。

### 仮想マシン（VM）の仕組み

仮想マシンは、ハイパーバイザという仕組みを使って、ハードウェアを仮想的に分割し、その上にゲスト OS を丸ごと起動します。

```
+------------------------------------------+
|              ホスト OS                     |
+------------------------------------------+
|            ハイパーバイザ                   |
+----------+----------+-------------------+
|  VM 1    |  VM 2    |  VM 3             |
| +------+ | +------+ | +------+          |
| |アプリ | | |アプリ | | |アプリ |          |
| +------+ | +------+ | +------+          |
| |ライブラリ| |ライブラリ| |ライブラリ|       |
| +------+ | +------+ | +------+          |
| |ゲストOS| | |ゲストOS| | |ゲストOS|       |
| +------+ | +------+ | +------+          |
+----------+----------+-------------------+
```

各 VM がゲスト OS を持つため、起動に数分かかり、GB 単位のディスク容量を消費します。

### コンテナの仕組み

コンテナは、ホスト OS の **カーネル（OS の中核部分）を共有** し、プロセスレベルで隔離を実現します。ゲスト OS は不要です。

```
+------------------------------------------+
|           ホスト OS カーネル               |
+------------------------------------------+
|         コンテナランタイム (Docker)         |
+----------+----------+-------------------+
| コンテナ1 | コンテナ2 | コンテナ3          |
| +------+ | +------+ | +------+          |
| |アプリ | | |アプリ | | |アプリ |          |
| +------+ | +------+ | +------+          |
| |ライブラリ| |ライブラリ| |ライブラリ|       |
| +------+ | +------+ | +------+          |
+----------+----------+-------------------+
  ゲスト OS なし -- カーネルを共有
```

### 比較表

| 項目 | 仮想マシン (VM) | コンテナ (Docker) |
|---|---|---|
| OS | 各 VM にゲスト OS が必要 | ホスト OS のカーネルを共有 |
| 起動時間 | 数分 | 数秒〜数百ミリ秒 |
| サイズ | 数 GB〜数十 GB | 数 MB〜数百 MB |
| パフォーマンス | ハイパーバイザのオーバーヘッドあり | ほぼネイティブ性能 |
| 集約密度 | 1 ホストに数十 VM | 1 ホストに数百〜数千コンテナ |
| 隔離レベル | 強い（カーネルレベル） | 中程度（プロセスレベル） |
| ポータビリティ | イメージが巨大で持ち運びにくい | イメージが軽量で配布しやすい |

:::message
コンテナは VM の「上位互換」ではありません。強い隔離が必要な場面（マルチテナント環境やセキュリティテスト）では VM が適しています。実際のクラウド環境では、VM の上でコンテナを動かすハイブリッド構成が一般的です。
:::

### どちらを使うべきか

用途によって使い分けるのが正解です。

| ユースケース | 推奨 | 理由 |
|---|---|---|
| マイクロサービス | コンテナ | 軽量で高速デプロイ、個別スケール可能 |
| 開発環境の統一 | コンテナ | 再現性が高く、`docker compose` で一発構築 |
| CI/CD パイプライン | コンテナ | 起動が高速で使い捨て可能 |
| レガシー OS の利用 | VM | 異なるカーネルが必要 |
| マルチテナント分離 | VM | 強い隔離が必要 |
| デスクトップ仮想化 | VM | GUI・ドライバ対応 |

## なぜ Docker を学ぶのか

### 1. 「環境の違い」問題を解決する

開発で最もストレスフルな問題の一つが、環境差異です。

- 「自分の PC では動くのに、同僚の PC では動かない」
- 「ステージング環境では OK だったのに、本番で障害が起きた」
- 「新メンバーの環境構築に 2 日かかった」

Docker はこれらの問題を根本的に解決します。Dockerfile に環境定義を記述すれば、誰がどこで実行しても同じ環境が再現されます。

```bash
# チームの誰もが同じ開発環境を一発で起動できる
docker compose up -d
```

### 2. 現代の開発ワークフローの標準

2026 年現在、以下の領域で Docker は事実上の標準になっています。

- **CI/CD**: GitHub Actions、GitLab CI などで、テストやビルドをコンテナ内で実行
- **マイクロサービス**: 各サービスをコンテナとして独立にデプロイ・スケール
- **クラウドネイティブ**: Kubernetes でコンテナのオーケストレーションを行う
- **開発環境**: `docker compose` でデータベースやキャッシュサーバーをローカルに起動

Docker を知らずに現代のソフトウェア開発を進めるのは、Git を知らずにチーム開発をするようなものです。

### 3. インフラの知識が体系的に身につく

Docker を学ぶ過程で、自然と以下の知識も身につきます。

- Linux の基本操作とファイルシステム
- ネットワークの仕組み（ポート、DNS、プロキシ）
- セキュリティの基本（権限管理、機密情報の取り扱い）
- アプリケーションのビルドとデプロイの流れ

つまり、Docker は単なるツールの習得にとどまらず、エンジニアとしての総合力を高める入り口になります。

### 4. 求人市場での需要

インフラエンジニアに限らず、バックエンドエンジニア、フロントエンドエンジニア、データサイエンティストなど、幅広い職種で Docker のスキルが求められています。「Docker 経験あり」は多くの求人で歓迎スキルまたは必須スキルとして挙げられています。

## Docker を支える技術（概要）

Docker は魔法ではありません。Linux カーネルが提供する複数の技術を組み合わせて実現されています。ここでは概要だけ押さえておきましょう（詳細は後の章で解説します）。

| 技術 | 役割 |
|---|---|
| **namespaces** | プロセスから見えるリソースの範囲を制限します。コンテナごとに独立したプロセス ID、ネットワーク、ファイルシステムを提供します |
| **cgroups** | CPU やメモリなどのリソース使用量を制限します。あるコンテナが資源を使い切って他に影響を与えることを防ぎます |
| **UnionFS (OverlayFS)** | ファイルシステムをレイヤー構造で管理します。ベースイメージの共有や効率的なストレージ利用を可能にします |

```
+------------------------------------------+
|            Linux カーネル                  |
|                                          |
|  namespaces    = 見える範囲の制限          |
|  cgroups       = 使える量の制限            |
|  OverlayFS     = レイヤー化ファイルシステム  |
+------------------------------------------+
```

:::message alert
macOS や Windows では Linux カーネルがないため、Docker Desktop は内部で軽量な Linux 仮想マシンを起動しています。ユーザーからはシームレスに見えますが、裏では VM 上でコンテナが動いています。
:::
